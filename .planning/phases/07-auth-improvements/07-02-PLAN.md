<objective>
Replace the 30-day long-lived JWT with a 15-minute access token + 7-day httpOnly refresh token system. Add the /refresh and /logout endpoints.

Purpose: The existing `signCustomerToken` issues 30-day JWTs — a stolen token gives an attacker 30 days of access with no revocation. This plan shrinks that window to 15 minutes and adds a stateful refresh mechanism with real logout (token deletion from DB). All token table writes depend on Plan 01 (db.js) having run first; however, since both Plan 01 and Plan 02 target different files (db.js vs customers.js), they can execute in parallel in Wave 1 — the tables must exist before the server starts, which Plan 01 guarantees before any request is served.

Output: customers.js with signAccessToken, issueTokenPair helper, updated login/signup, new /refresh endpoint, new /logout endpoint.
</objective>

```javascript
  return jwt.sign(
    { role: "customer", id, phone: phone || null },
    process.env.JWT_SECRET,
    { expiresIn: "15m" }
  );
}

function generateToken() {
  return crypto.randomBytes(32).toString('hex'); // 64-char hex
}

function hashToken(token) {
  return crypto.createHash('sha256').update(token).digest('hex');
}

// Issues access + refresh token pair. Sets httpOnly cookie and returns accessToken.
function issueTokenPair(res, customerId, phone) {
  const accessToken = signAccessToken(customerId, phone);
  const rawRefresh = generateToken();
  const refreshHash = hashToken(rawRefresh);
  const refreshExpiry = new Date(Date.now() + 7 * 24 * 60 * 60 * 1000).toISOString();

  db.prepare(
    "INSERT INTO refresh_tokens (customer_id, token_hash, expires_at) VALUES (?, ?, ?)"
  ).run(customerId, refreshHash, refreshExpiry);

  res.cookie('refreshToken', rawRefresh, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 7 * 24 * 60 * 60 * 1000,
  });

  return accessToken;
}
```

**Route 1 — POST /api/customers/refresh:**
```javascript
// ── POST /api/customers/refresh ────────────────
router.post('/refresh', (req, res) => {
  try {
    const inbound = req.cookies?.refreshToken;
    if (!inbound) return res.status(401).json({ error: 'No refresh token' });

    const inboundHash = hashToken(inbound);
    const row = db.prepare(
      "SELECT * FROM refresh_tokens WHERE token_hash = ? AND expires_at > strftime('%Y-%m-%dT%H:%M:%SZ','now')"
    ).get(inboundHash);

    if (!row) return res.status(401).json({ error: 'Invalid or expired refresh token' });

    // Rotation: delete old token row first
    db.prepare("DELETE FROM refresh_tokens WHERE id = ?").run(row.id);

    // Issue new token pair (inserts new refresh_tokens row + sets cookie)
    const customer = db.prepare("SELECT id, phone FROM customers WHERE id = ?").get(row.customer_id);
    if (!customer) return res.status(401).json({ error: 'Customer not found' });

    const accessToken = issueTokenPair(res, customer.id, customer.phone);
    res.json({ accessToken });
  } catch (err) {
    logger.error(err, 'POST /api/customers/refresh error');
    res.status(500).json({ error: 'Token refresh failed' });
  }
});

// ── POST /api/customers/logout ─────────────────
router.post('/logout', (req, res) => {
  try {
    const inbound = req.cookies?.refreshToken;
    if (inbound) {
      const hash = hashToken(inbound);
      db.prepare("DELETE FROM refresh_tokens WHERE token_hash = ?").run(hash);
    }
    res.clearCookie('refreshToken', { path: '/' });
    res.json({ success: true });
  } catch (err) {
    logger.error(err, 'POST /api/customers/logout error');
    res.status(500).json({ error: 'Logout failed' });
  }
});
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client cookie → /refresh endpoint | Refresh token arrives as httpOnly cookie; must be validated against DB hash before issuing new tokens |
| Client → /logout endpoint | Logout must succeed even without a cookie (idempotent) — do not return error if no cookie present |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02-01 | Information Disclosure | refresh_tokens table | mitigate | Only SHA-256 hash stored in DB via `hashToken(rawRefresh)` — raw token never written to DB |
| T-07-02-02 | Elevation of Privilege | Access token lifetime | mitigate | `expiresIn: "15m"` — stolen access token is unusable after 15 minutes |
| T-07-02-03 | Repudiation | Refresh token rotation | mitigate | Old token row is DELETEd before new row is INSERTed — prevents replay of rotated token |
| T-07-02-04 | Tampering | CSRF on /refresh | mitigate | `sameSite: 'lax'` on cookie — cross-site POST cannot trigger cookie send; `credentials: include` must be explicit on frontend |
| T-07-02-05 | Information Disclosure | XSS stealing tokens | mitigate | Access token returned in JSON body (kept in JS memory by client, not localStorage); refresh token in httpOnly cookie (not accessible to JS) |
| T-07-02-06 | Denial of Service | Token table growth | accept | Expired tokens cleaned up by runRecoveryTask (Plan 04); 15min access token means refresh happens at most every 15min per active session |
</threat_model>
