<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB schema → application | Token tables must enforce UNIQUE on token_hash to prevent hash collision token reuse |
| Runtime startup → env vars | Missing RESEND_API_KEY in production must fail loudly, not silently degrade email |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01-01 | Information Disclosure | refresh_tokens.token_hash | mitigate | Store SHA-256 hash (not raw token) — enforced by UNIQUE NOT NULL column constraint |
| T-07-01-02 | Tampering | cookie-parser mount order | mitigate | Mount cookieParser() before body-parser middleware so req.cookies is populated before any route handler reads it |
| T-07-01-03 | Denial of Service | token tables (unbounded growth) | mitigate | Cleanup added in Plan 04 (runRecoveryTask extension); schema uses ON DELETE CASCADE so customer deletion removes all tokens |
| T-07-01-04 | Elevation of Privilege | RESEND_API_KEY missing in production | mitigate | Production env guard in server.js calls process.exit(1) on startup if RESEND_API_KEY is absent |
| T-07-01-05 | Tampering | FOREIGN KEY constraints | mitigate | All token tables declare FOREIGN KEY (customer_id) REFERENCES customers(id) ON DELETE CASCADE — orphaned tokens are impossible |
</threat_model>
